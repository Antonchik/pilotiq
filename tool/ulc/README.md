# tool/ulc — конвертер банка вопросов ULC

Превращает официальные PDF «Przykładowe pytania egzaminacyjne» (ULC, обновление 01.08.2024; PDF созданы 2024-07-26)
в детерминированные JSON-банки `assets/data/bank_{ppla,pplh,spl,bpl}.json` (схема 2) и пишет отчёты в `reports/`.

| лицензия | PDF | язык |
|---|---|---|
| PPL(A) | `ppla_eng.pdf` | PL + EN в одной ячейке |
| PPL(H) | `pplh_eng_2023.pdf` | PL + EN в одной ячейке |
| SPL | `spl.pdf` | PL |
| BPL | `bpl.pdf` | PL |

URL, SHA-256 и даты — в `sources.json`. У `bpl.pdf` прямой URL неизвестен (файл получен от владельца): указана страница ULC.

## Как повторить конвертацию

1. Скачайте PDF вручную в браузере со страницы
   <https://ulc.gov.pl/personel-lotniczy/komisja-egzaminacyjna/egzaminy-teoretyczne/przykladowe-pytania-egzaminacyjne>
   (сайт защищён от ботов, автоматическая загрузка не предусмотрена) и положите файлы в `tool/ulc/sources/` под именами из таблицы.
   Каталог `sources/` и `cache/` исключены из git (`tool/ulc/.gitignore` и корневой `.gitignore`).
2. `pip install -r tool/ulc/requirements.txt` (pdfplumber 0.11.10, Python 3.10+).
3. `python3 tool/ulc/convert.py --all` (или `--licence ppla`). Первый разбор PPL(A) занимает несколько минут,
   сырые строки таблиц кэшируются в `tool/ulc/cache/`.
4. `python3 tool/ulc/validate.py assets/data/bank_*.json` — проверка банков (exit ≠ 0 при нарушении).
5. `python3 -m unittest discover -s tool/ulc/tests` — тесты конвертера.

Конвертер сверяет SHA-256 каждого PDF; если файла нет или хеш другой, он останавливается с понятной ошибкой
(новая версия PDF должна быть просмотрена и внесена в `sources.json` сознательно).
Повторный запуск даёт побайтно тот же результат (без меток времени, сортировка по `id`).

## Как устроен разбор

* Таблицы PDF (7 колонок `L.p. | NUMER | PYTANIE | ODP1..ODP4`, ODP1 — верный ответ) читаются pdfplumber с сохранением переносов.
  Строка без L.p. и NUMER — продолжение предыдущей записи на следующей странице, ячейки склеиваются.
* Перенос внутри слова (в PDF у такой строки нет завершающего пробела) склеивается без пробела; перенос на пробеле — с пробелом.
* NUMER нормализуется (`PL 100-0126` → `PL100-0126`), HTML-сущности декодируются, пробелы схлопываются.
* Предмет определяется по префиксу NUMER (`TOPIC_TO_SUBJECT` в `convert.py`; зеркало `catalog.topicPrefixToSubject`, `PL021` → `aircraft_general_knowledge`).
* Отбрасываются (с записью в отчёт: страница и причина): пустой/невалидный NUMER, пустой вопрос, любой из 4 пустых ответов,
  неизвестный префикс темы.
* Дубли схлопываются: тот же NUMER и тот же польский текст вопроса и всех ответов **без учёта пробелов и регистра**
  («200 m.» = «200m.», «lotu ?» = «lotu?»; знаки и цифры значимы: «-3» ≠ «3»). Из группы дублей остаётся запись с лучшим
  английским текстом, правило детерминировано: (1) меньше ячеек без EN, (2) меньше EN-текстов, начинающихся со строчной буквы
  (опечатка «wwith»), (3) меньше неразделённых ячеек, (4) при равенстве — первая по порядку в PDF. Схлопнутые пары перечислены в отчёте.
* В PDF есть невидимые пробелы, лежащие поверх букв (`od s t r o m ego`). Конвертер отбрасывает пробельные символы, перекрывающие
  букву той же строки больше чем на 0,5 pt; настоящий межсловный пробел только касается соседей.
* ID вопроса: `NUMER`, если он в файле уникален, иначе `NUMER~<6 hex SHA-1 от «вопрос\nверный ответ»>`, где тексты — полный склеенный
  текст ячеек из PDF **до** разделения PL/EN (NFC, пробелы нормализованы; для группы дублей берётся первая запись по порядку).
  Поэтому ID не зависит ни от лексикона, ни от параметров разделителя, ни от порядка строк.
  Если совпали и вопрос, и верный ответ (различаются только неверные ответы) — хеш считается по вопросу и всем 4 ответам.
  Все варианты одного NUMER сохраняются.
* **Разделение PL/EN** (только PPL(A)/(H)): в PDF польский и английский текст идут одной ячейкой подряд, границы нет.
  Граница ищется эвристикой: лексикон «слово → вероятность PL/EN», построенный из прежних данных проекта (`legacy/`),
  плюс структурные признаки (конец предложения, одинаковая завершающая пунктуация, соотношение длин, заглавная буква EN).
  Неуверенные случаи (малая разница оценок, PL-часть без знака препинания на конце, начало EN-части повторяется дальше)
  **не режутся**: в `pl` остаётся полный текст ячейки, `en = null` (UI покажет PL). Так лучше, чем обрезать польский текст.
  Ячейки без букв (числа) копируются в оба языка. Точность на отложенной выборке: `python3 tool/ulc/convert.py --eval-split`.
* `legacy/` — прежние JSON приложения (до 2024): нужны только как лексикон для разделения и для раздела «Сравнение» в отчётах.
  Конвертер от них не берёт ни одного вопроса.

## Схема выхода

```json
{"schema":2,"licence":"ppla","source":{"file":"ppla_eng.pdf","sha256":"…","date":"2024-07-26","kind":"pdf"},"questions":[
{"id":"PL010-0001","number":"PL010-0001","topic":"PL010","subject":"air_law","q":{"pl":"…","en":"…|null"},"a":[{"pl":"…","en":"…|null"},…4],"correct":0}
]}
```

`correct` всегда `0` (верный ответ в источнике — ODP1; перемешивание — задача приложения при показе).

## Известные особенности источника

* В PDF встречаются дубли NUMER с разным текстом (варианты) — сохранены все; в одной симуляции приложение должно брать один вариант на NUMER.
* Встречаются опечатки и артефакты самого источника (`/n` в конце EN-текста, одинаковые тексты двух ответов, «Mm» вместо «NM»);
  конвертер ничего не «исправляет» в тексте.
