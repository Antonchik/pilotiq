# План проверки на устройствах

Порядок и подготовка. Подробные сценарии и ожидаемые тексты экранов — `docs/release-checklist.md` (разделы 4–7 и 11.5); здесь они не повторяются, только ссылки. Ничего из этого на устройстве я не запускал, поэтому в сценариях есть места с пометкой «проверить».

## 0. Что нужно

- Android 13 или новее и iPhone с iOS 15 или новее. По возможности ещё планшет или складной Android (раздел 7.5 чек-листа).
- Ключи RevenueCat: `appl_…` и `goog_…` из Project Settings → API keys. Секретный ключ `sk_…` не нужен. Храните ключи вне проекта, например в `~/pilotiq-keys.env`:

  ```
  RC_API_KEY_ANDROID=goog_...
  RC_API_KEY_IOS=appl_...
  ```

- Тестовые аккаунты:
  - Android: ваш Google-аккаунт в Setup → License testing и в списке тестировщиков Internal testing; приглашение принято.
  - iOS: Sandbox-аккаунт в App Store Connect (Users and Access → Sandbox → Test Accounts); на iPhone Настройки → App Store → Sandbox Account.
- Продукты и цены созданы в обеих консолях, offering `default` в RevenueCat текущий (сделано).
- Учётные данные Google для RevenueCat загружены. Они начинают работать до 36 часов, до этого покупки Android могут не проходить, это не ошибка приложения.

## 1. Быстрая проверка без покупок (около 30 минут)

Сборка без ключей. Покупки в ней недоступны, остальное работает.

```
flutter run                      # отладочная, на подключённом телефоне
```

1. Чистая установка. Онбординг: лицензия и язык, дата экзамена (можно пропустить), цель дня, напоминания (можно пропустить). Нужны три вкладки: «Dziś», «Przedmioty», «Profil» (раздел 7.2).
2. «Przedmioty» → «Prawo lotnicze» → «WSZYSTKIE PYTANIA»: ответить на вопрос, поставить закладку, ошибиться и увидеть число в «MOJE BŁĘDY» (раздел 7.3).
3. Симуляция: запустить, ответить на несколько вопросов, свернуть приложение, вернуться; убить приложение, открыть снова, продолжить (раздел 7.4).
4. Режим полёта: чистый запуск, обучение и симуляция работают (раздел 7.8).
5. Пэйвол без ключа: должно быть сообщение «Zakupy nie są dostępne w tej wersji aplikacji.», без падений.
6. Материалы: конспекты и первое объяснение подтемы открыты (раздел 11.5).
7. Экран «O aplikacji»: версия, ссылки, оговорка о связи с ULC, источник и дата базы.

Что записать: падения, обрезанный текст, всё, что не совпало с чек-листом.

## 2. Сборки с ключами

```
set -a; source ~/pilotiq-keys.env; set +a
flutter run --dart-define=RC_API_KEY_ANDROID=$RC_API_KEY_ANDROID          # Android, отладка
flutter build appbundle --release --dart-define=RC_API_KEY_ANDROID=$RC_API_KEY_ANDROID
flutter build ipa --release --dart-define=RC_API_KEY_IOS=$RC_API_KEY_IOS
```

`.aab` загружается в Internal testing (Google Play), `.ipa` — в TestFlight через Transporter или Xcode Organizer. Версия в `pubspec.yaml` `2.0.0+15`; при повторной загрузке код сборки увеличивайте.

## 3. Покупки (раздел 6.4)

Порядок:

1. **Android, отладочная сборка с ключом.** Пэйвол показывает три плана с ценами из Play, у «3 miesiące» строка о пробном периоде, метка «Najlepszy wybór» только у «Na zawsze».
2. Купить «1 miesiąc» → экран «Dziękujemy!», Premium открыт без перезапуска. В RevenueCat → Customers клиент с активным `premium`.
3. Отменить покупку в системном окне → без сообщения об ошибке.
4. «Przywróć zakupy» на аккаунте с покупкой и без. Без покупки сообщение: «Nie znaleziono aktywnych zakupów na tym koncie sklepu.»
5. Купить «3 miesiące» с пробным периодом и «Na zawsze». Для подписок в тестовом режиме месяц длится около 5 минут: проверьте истечение и снятие Premium.
6. Потеря сети в момент покупки и двойное нажатие: одна покупка, без зависшего экрана.
7. То же на iOS через TestFlight и sandbox-аккаунт.

Offline и перевод часов (раздел 6.4, последние пункты) лучше оставить на конец: после них Premium может вести себя нетипично.

## 4. Обновление поверх 1.2.0 (раздел 7.1)

Нужна установка 1.2.0 из магазина с реальными данными. **Важно:** прежняя версия подписана ключом Google Play, а сборка с вашим ключом загрузки при установке через `adb` не встанет поверх неё («несовместимая подпись»). Поэтому на Android проверяйте так: загрузить `.aab` в Internal testing и обновиться из Google Play. На iOS обновление поверх App Store версии через TestFlight работает штатно.

Что смотреть: приложение запускается, тема сохранилась, нет сообщения «Zapisane dane były uszkodzone», старые результаты в «HISTORIA» помечены «Przed wersją 2.0».

## 5. Материалы (раздел 11.5)

- Бесплатный аккаунт: первые 3 объяснения подтемы открыты, четвёртое закрыто («Objaśnienie dostępne w Premium» и «Odblokuj w Premium»).
- Спорный вопрос: виден блок «Pytanie sporne». Пример: `PL010-0446` в варианте b66d2091.
- Вопрос на устаревшей норме: для бесплатного аккаунта пометка «Pytanie opiera się na nieaktualnych przepisach», строка «Opis zmian… w Premium» и кнопка «Odblokuj w Premium». Пример: `PL010-0244`. С Premium показан текст пометки полностью.
- «Zgłoś błąd»: пока адрес не задан (`materialsReportEmail`), открывается диалог с кнопкой «Kopiuj».
- Конспекты: первый раздел открыт, следующие «Ten rozdział jest dostępny w Premium».
