# Чек-лист выпуска Pilotiq 2.0

Для владельца приложения. Документ самодостаточен: по нему можно идти сверху вниз перед выпуском.

## 1. Как пользоваться документом

**Главное.** Код версии 2.0 проверен только анализатором и автотестами. Ни одна сборка для Android или iOS не запускалась, приложение не ставилось ни на одно устройство, покупки и консоли магазинов не открывались: в среде разработки не было Android SDK, Xcode, устройств и доступа к магазинам и RevenueCat. Всё перечисленное ниже — то, что можете проверить только вы.

**Что проверено автоматически.** `flutter analyze` без замечаний и полный набор автотестов (`flutter test`) на Flutter 3.50.1 / Dart 3.14. Тесты покрывают: чтение файлов данных версии 1.2.0 и перенос из них темы и прежних результатов; банк вопросов; расчёты (повторение, готовность, серия, подсчёт результата экзамена); обучение и дневной лимит; симуляцию экзамена, включая сбои сохранения, «убийство» приложения и перевод часов; экран «Сегодня», онбординг и настройки; расписание напоминаний; покупки и пэйвол на подменном сервисе покупок; оба языка интерфейса; вёрстку при крупном шрифте. Часть тестов прогонялась в нескольких часовых поясах.

**Чего автотесты не покрывают.** Сборку и подпись; работу плагинов на реальной системе; доставку уведомлений; настоящие покупки, RevenueCat и магазины; обновление поверх установленной 1.2.0 на устройстве; внешний вид на реальных экранах.

**Обозначения.**

- `- [ ]` — действие и ожидаемый результат в виде «сделать → должно быть».
- **[ПРОВЕРИТЬ: …]** — утверждение, которое при подготовке не удалось подтвердить; его нужно проверить вам.
- Связанные документы: `README.md` (раздел «Сборка и ключи»), `docs/monetization.md` (модель, цены, перенос подписчиков), `tool/ulc/README.md` и `tool/ulc/reports/` (банк вопросов).

Перед началом повторите автоматическую проверку на своей машине:

- [ ] `flutter pub get && flutter analyze` → «No issues found!».
- [ ] `flutter test` → все тесты проходят.
- [ ] `dart run tool/l10n/merge_arb.dart --check` → код возврата 0 (строки EN и PL согласованы).

## 3. Решения, которые нужно принять или подтвердить

Юридического заключения здесь нет. Известно следующее: вопросы взяты из PDF, которые ULC сам публикует на странице «Przykładowe pytania egzaminacyjne»; явных условий коммерческого использования на сайте не найдено; разрешение ULC не получено. По вашему решению формулировки оставлены оригинальными, в приложении указаны источник и дата базы и показана оговорка «не связано с ULC». Подробнее — `docs/monetization.md`, раздел 7.

## 4. Сборка Android

Ни одна Android-сборка не запускалась. Совместимость плагинов с новым Gradle проверена только по их исходным файлам.

### 4.1. Окружение

- [ ] Flutter 3.50.1, JDK 17, Android SDK Platform 37, NDK 28.2.13676358, CMake из Android SDK → `flutter doctor` не показывает ошибок по Android.
- Версии в проекте (скачиваются сами): Gradle 9.5.0, Android Gradle Plugin 9.3.1, Kotlin 2.4.20; `compileSdk` 37, `targetSdk` 36, `minSdk` 24.
- [ ] Не включать Gradle configuration cache: с ним проверка наличия ключей подписи пропускается.

### 4.2. Версия

- [ ] Открыть `pubspec.yaml`, строку `version:` → стоит `2.0.0+15`. На момент подготовки чек-листа там было `1.2.0+14`; если значение не изменено — поднять. Код сборки должен быть больше 14.

### 4.3. Команды

- [ ] `flutter build apk --debug` → сборка проходит. Ключи для неё не нужны. Это первая проверка связки Gradle 9.5.0 + AGP 9.3.1 + Kotlin 2.4.20 со всеми плагинами.
- [ ] Временно убрать `android/key.properties` и запустить release-сборку → сборка падает с сообщением «android/key.properties not found - release build requires the upload keystore». Вернуть файл.
- [ ] Release-сборка с ключом RevenueCat:

  ```
  flutter build appbundle --release \
    --dart-define=RC_API_KEY_ANDROID=<публичный ключ Android из RevenueCat>
  ```

  → получен файл `.aab`, подписанный вашим ключом загрузки.

### 4.4. Если сборка не проходит

Места, где сбой наиболее вероятен:

- Плагины на старом синтаксисе Gradle (Groovy): `purchases_flutter` (собирается с Java 1.8 — ожидается только предупреждение) и `flutter_timezone`.
- Пакеты `jni`, `jni_flutter` и `purchases_flutter` задают `namespace` условно, в зависимости от версии AGP.
- Пакет `jni` (его подтягивает `path_provider_android` 2.3.1) собирает нативную часть через CMake.

Запасной вариант, если `jni` не собирается: зафиксировать `path_provider_android` на версии 2.2.23 через `dependency_overrides` в `pubspec.yaml`, затем `flutter pub get` и повторить сборку.

### 4.5. Что проверить в готовом пакете

- [ ] `apksigner verify --print-certs` → сертификат тот же, что у прежнего ключа загрузки.
- [ ] `aapt2 dump badging` → `targetSdkVersion` 36; идентификатор приложения `antonchik.anton.pilotiq`; код версии больше 14.
- [ ] В том же выводе нет разрешений `SCHEDULE_EXACT_ALARM` и `USE_EXACT_ALARM`; есть `POST_NOTIFICATIONS`, `RECEIVE_BOOT_COMPLETED`, `com.android.vending.BILLING`, `INTERNET`.
- [ ] `zipalign -c -P 16 -v 4` → проверка выравнивания под страницы 16 КБ проходит для всех нативных библиотек, включая `libdartjni.so`.
- [ ] Play Billing Library. По файлам плагина `purchases_flutter` 11.0.4 используется версия 9.1.0 (Google Play требует не ниже 8). Сборкой это не подтверждено. [ПРОВЕРИТЬ: Play Console принимает пакет без предупреждения о версии Billing Library.]
- [ ] Установить **release**-сборку на устройство → приложение запускается и видит сохранённые данные. Это отдельная проверка: в release-сборке код сжимается (R8), а от определения папки данных зависит всё хранилище.

- [ ] Тестовый аккаунт с активной подпиской, купленной в 1.2.0 → установить 2.0 поверх → Premium появляется без покупки.
- [ ] Перезапустить приложение → повторного запроса нет, Premium на месте.
- [ ] Включить авиарежим и перезапустить → Premium действует (берётся из сохранённого статуса).
- [ ] iOS: при первом запуске после обновления не появляется системный запрос входа в Apple ID. [ПРОВЕРИТЬ: по исходным файлам плагина выяснить это не удалось.]

## 10. Известные ограничения версии 2.0

Это свойства версии, а не пропущенные ошибки. О них стоит знать при ответах пользователям.

**Платформы и перенос данных**

- Пользователи iOS 13–14 остаются на 1.2.0: минимальная версия iOS — 15.0.
- Позиция «продолжить с вопроса N» из 1.2.0 не переносится: порядок вопросов в банке изменился. Переносятся тема и итоги прежних попыток.
- Промежуточной версии с двумя платёжными системами нет: перенос подписчиков проверяется только до выпуска.

**Банк вопросов**

- В PPL(A) 110 из 2369 вопросов (около 4,6 %), в PPL(H) 94 из 1908 (около 4,9 %) показываются без разделения языков: польский и английский текст идут подряд в одном поле на любом выбранном языке. Так сделано намеренно там, где автоматическое разделение было ненадёжным. Списки с причинами — в `tool/ulc/reports/ppla.md` и `pplh.md`.
- SPL (1354 вопроса) и BPL (903 вопроса) — только на польском: в источнике нет английского текста.
- Тексты не исправлялись. В источнике есть опечатки и артефакты: лишнее «/n» в конце английского текста, «Mm» вместо «NM», одинаковые тексты двух ответов (PL020-0253 и PL040-0248 в PPL(A) и PPL(H); PL040-0249 в SPL и BPL).
- Спорные ключи ответов PL010-0446…0451 и PL010-0441 / 0442 / 0444 оставлены как в источнике (раздел 3.2).
- Объяснений к ответам нет: в источнике ULC их нет.
- Второй вариант вопроса показывается в обучении только после всех ещё не тронутых номеров предмета (раздел 3.6). В одной симуляции экзамена двух вариантов одного номера не бывает.

**Экзамен и учебные расчёты**

- Экзаменационное время считается по часам устройства. От перевода часов назад приложение защищено (времени не становится больше, потраченное не убывает); перевод часов вперёд завершает экзамен по времени.
- Параметры экзамена (число вопросов и время по предметам, порог 75 %) взяты из версии 1.2.0 и при подготовке 2.0 с действующими правилами ULC не сверялись. [ПРОВЕРИТЬ: соответствие действующим правилам экзамена.]
- Оценка готовности и интервалы повторения не проверены на реальных пользователях; в приложении готовность подписана «ориентировочно».
- При крупном системном шрифте в автотестах допущено переполнение в системном диалоге выбора даты (раздел 7.7).

**Покупки и наблюдение**

- Без сети статус Premium берётся из сохранённого значения и действует до конца оплаченного периода; при ответе RevenueCat «не активен» Premium снимается сразу.
- Аналитики и сбора сбоев нет: место показа пэйвола пишется только в отладочный журнал.
- Дневной лимит и другие границы бесплатного доступа заданы в коде: их изменение требует выпуска версии. Состав и порядок планов на пэйволе меняются в RevenueCat без выпуска.

**Технический долг**

- Flutter 3.50 помечает устаревшим основной набор виджетов (`package:flutter/material.dart`); переход на новый пакет не сделан и остаётся отдельной задачей. На момент подготовки чек-листа предупреждения об устаревших API в настройках анализатора были отключены.
